# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed

- Recent and Favorites: the loading placeholder now matches the view you are in. In list view it is the table, with its Name / Last active / Pages header and one placeholder row per file, at the real rows' height and column widths; grid view keeps its placeholder cards, now exactly the height of a real card. There is one row or card per file the list last had (up to 20; 6 if Lector doesn't know yet). The placeholder only appears if loading takes longer than about 150ms, stays at least 300ms once it has, and then fades into the real list, which lands in exactly the same place.
- Recent and Favorites open faster. The list no longer waits for every thumbnail: the rows appear first, each thumbnail slot shimmers until its picture is ready, and the pictures fill in a few at a time from the top. Going back to Home from Settings, or reloading, now shows the list about 100ms after the page is up instead of 250-450ms, and with a cold cache the rows appear about 400ms sooner.

- Reader header: "‹ Library" is now a proper back button (36px tall, with hover, pressed and keyboard-focus states), and it sits on the same text baseline as the document title. A long title ends in "…" and shows in full when you point at it; it no longer pushes the page controls. The previous/next chevrons, the page box, "of N" and the zoom percentage are all 32px and share one centre line. The page box fits five digits: click it and the number is selected, type a page and press Enter to go there, Esc puts it back, and a number past the last page goes to the last page (letters are ignored), with no error message.
- The reader's left toolbar no longer has a "?" button. It opened the same "What can I say?" list as the labelled button in the footer, which stays, along with the `?` key and the spoken "what can I say".
- The reader's left toolbar no longer shows "OFFLINE" (it also broke as "OFF / LINE"). Lector is always offline, so it was a constant, not a status; the library sidebar and the voice card still say so. The toolbar's groups are spaced evenly from the top.

- The saved theme now reaches each page from Lector itself, which writes it into the page as it sends it, instead of from a copy kept in the web view's storage. Pages still open in your theme from the very first frame, and nothing needs resetting: the theme was always saved in Lector's settings file, and that is where it is read from.
- Page spacing is now one shared set of rules instead of a number per page. The gap between the page title row and what is under it is 32px on Recent, Favorites and Settings (it was 16px on Recent and Favorites and 24px on Settings), so the title and everything below it line up when you switch pages. The page padding, the space between Settings sections, the dialogs' padding (Open PDF, "What can I say?", the save and remove confirmations) and the reader's toolbar and footer sides now each come from one named setting in `theme.css`. Nothing else moves: the dialogs and the reader measure exactly the same as before, and the title sits at the same position on every page at the default and the smallest window size. Empty and no-match cards stay centred in the space under the header.
- List view: the three column headers (Name, Last active, Pages) now have the same weight and colour. The sorted one used to be bolder and darker, so Last active looked heavier than the others; it is now marked by its arrow alone.
- In the list view, the "⋯" menu no longer offers "Add to Favorites" / "Remove from Favorites". The star beside it already does that, so the menu only repeated it. The menu is now Open, Show in folder and (in Recent) Remove from Recent. Starring by voice is unchanged.
- The search button and the grid/list toggle in the page header are smaller (40px tall instead of 48px; the toggle's buttons are 32px with 18px icons), and Open PDF is 40px to match, so the row no longer dwarfs the title.
- Library pages (Recent, Favorites) got a round of fixes to their header, list and cards, built once in shared files so every page that has these parts gets them: `frontend/shared/library-header.css` (header row, count, search, view toggle) and `frontend/pages/recent-card.js` (grid card).
  - The count beside the title is plain text now ("12 files", "1 file", "3 of 12 files" while searching) instead of a small chip that was nearly invisible in dark mode. It meets 4.5:1 in all three themes (7.0 to 7.6 measured).
  - List view column headers: the inactive ones (Name, Pages) were too faint next to the sorted one. They are now at least 7:1 in every theme; the sorted column is told apart by a heavier weight and its up or down arrow, not by a big colour gap. The Last active and Pages cells are a notch darker too. Nothing else in the list changed.
  - The grid/list toggle has even 4px spacing and a solid accent fill on the active one. The search field, the toggle and Open PDF are all 40px tall (the toggle's buttons are 32px with 18px icons). The toggle has the same hover, pressed and keyboard-focus states as the other controls.
  - Search is a search icon until you open it. Click it (or press Ctrl+F or "/") and the field grows to the left over the empty space in about 200ms, with focus in it, and nothing else in the row moves. Click the icon again, press Esc, or click away while the field is empty to close it; closing clears the search. A field with text stays open. The list now filters after you pause typing (200ms) rather than on every key. With "reduce motion" on it opens instantly. This replaces the old rule that only collapsed it in narrow windows.
  - Grid cards: the star and the trash button now sit together inside the top-right corner of the thumbnail (8px in, 32px each), on solid chips that stay legible over white and dark pages, instead of straddling its edge. They appear on hover or keyboard focus; a starred star stays visible. The top-left corner stays free for the voice numbers. Removing still asks first and ends on the Undo toast, by click or by voice. Pressing Enter or Space on a focused star or trash now does that button's job; before, on a grid card it opened the PDF instead.
  - The trash icon was redrawn (lid, handle, body, two lines, same weight as the other icons) and is drawn at 18px so it matches the star. It is neutral until you point at it, then turns a quiet red. It is also the icon on the list menu's Remove item and the remove confirmation.
  - A starred star is now gold, filled, in both grid and list (it was the green accent). Gold is its own colour in each theme and is kept apart from the orange used for voice. An unstarred star is a neutral outline.
- "What can I say?" is now one list, the same on every screen (Recent, Favorites, Settings and the reader), and its copy is true: "Say these phrases exactly. Lector only recognizes the commands listed here. Every command also has a button or shortcut." (it used to say the phrases were "examples, not magic words", but only the listed phrases work). Every card now shows every phrase that works for that command ("next page" has six, the list showed two), nothing is listed that doesn't work, and phrases with a variable show the real range ("open number 1–7", "go to page 1–300") instead of one made-up example. Commands that were missing are listed too: undo, redo, "go home", "start search" and the commands for the Open and Save dialogs. It is one column of sections, with your current screen's first, then the rest in a fixed order; a section that works elsewhere says where. Search matches phrases, descriptions and the button or shortcut text, and shows "No commands match" with a Clear button. Title, description and search are a fixed header; only the list scrolls, with a line under the header once it has. The search box's focus ring is no longer cut off at the top and no longer appears just because the list opened (use Tab, "/" or Ctrl+F to reach the box). The `?` key now opens it on every screen, not only in the reader.
- Scrollbars now stop 8px short of both ends, vertical and horizontal, everywhere (every page, the Open PDF dialog's tree and file list, "What can I say?", the reader), so the thumb no longer touches the window edge or title bar. Nothing moves or reflows, and the auto-hide is unchanged.
- Scrolling the app does by itself is now short and smooth: moving to the next or previous page or a page number in the strip layout, the Open dialog's folder tree following the folder you click, the arrow keys in the strip and "scroll down" by voice. It takes 200ms. It stays instant where animation would only get in the way: when a page or dialog first opens, when zooming, for a jump of more than a few screens (page 3 to page 300 lands straight away instead of sweeping past every page in between), and with "reduce motion" on. Mouse wheel and touchpad scrolling are untouched: they are still the browser's own.
- Switching theme (Light, Dark, Sepia) is now one smooth fade of the whole window, in Settings and in the reader. Before, each element faded on its own timer, which could start late and be cut short, so on a slower machine the change could land as a snap well after the click. Now the old and new looks dissolve together in 200ms: the page, sidebar, cards, shadows, scrollbars and the chosen card's check and ring all move as one, and the open PDF page does not blink or reload. With "reduce motion" on, the theme changes instantly.
- Dark and Sepia no longer flash light when the app opens. The app now remembers your theme between launches before the first screen is drawn, and the window's background matches it.
- Settings (and the other screens' shared controls) feel less static. Cards, toggles, the checkbox, sidebar items and the "What can I say?" link now have a visible hover, a pressed state and a clear keyboard-focus ring. The theme and option cards are clickable all over, not just on the radio dot, and are reachable with Tab (arrow keys move between options). Every card (Recent's grid cards, and Settings' theme, voice and option cards) now responds the same way to the pointer and keyboard focus: the border turns accent, the card gains a shadow and rises 2px. The chosen option now has a soft green fill as well as its heavier edge, and the option cards sit a little further apart, so hovering the card under the chosen one no longer looks like a second chosen card. Switching theme crossfades instead of snapping. Settings and Home fade in section by section when you open them (not again when you change a setting). Toggles slide, the radio dot and ring animate in, the checkbox tick draws in, and the chosen theme's check badge fades in. With "reduce motion" on, nothing moves.
- Voice activation cards now match the option cards (same surface, border, corners and padding). The card stays that same white surface whether it is on or off; the state shows in the toggle and its "On"/"Off" label, and an off card's text is dimmer. Voice still can't switch voice activation off; only the toggles do.
- Settings: "Don't ask again — just do this every time" now sits tight under "When I save highlights", indented under its options, instead of floating between that section and the next. "Space" and the wake phrase are drawn as flat read-only values (not button-like chips) with a small "fixed for now" note.
- The save-changes dialog's two options use the same cards, so they are focusable and animate the same way.
- Motion is now one set everywhere: 120ms for hover/press feedback, 200ms for state changes, one ease-out curve. The bounce on toggles, radios, the checkmark and the folder tree is gone.
- Home has one header row instead of a top bar plus a heading row: the title and count on the left; search, the grid/list toggle and Open PDF on the right. Open PDF in the header shows only on Recent and only when it has files (an empty list has the card's own button, and Favorites has none). Search and the toggle hide when there is nothing to search or switch. Controls hide without moving anything else. Settings uses the same header row so titles line up across pages.
- While "What can I say?" is open, voice only hears its own commands ("got it", "go back", "cancel", and "start search"). Before, "next page" would keep turning pages behind it.
- Saying "overwrite the original" in Settings now asks first; say "confirm overwrite" or "cancel". Clicking the option still applies it straight away.
- The sidebar voice box says "CHECKING VOICE" until the speech engine has actually answered, and reports a problem if voice couldn't start on that screen, instead of always saying "VOICE READY".
- "Show recent files" now works from Settings and the reading view too (it is now "go to Recent").
- The empty-state card is solid rather than dashed, and its "TRY SAYING" examples are flat tinted labels rather than bordered pills, so they no longer look clickable.
- The "What can I say?" link in the sidebar has a larger click target (24px tall).
- Home's Recent list view is now one table card with a header row and hairline dividers, instead of a separate card for every PDF. Columns are Name, Last active and Pages; the Progress column and its bars are gone. Names show the PDF's own title when it has one (the filename otherwise), and long names keep their distinguishing ending visible (e.g. "…Mandate (highlighted)"), with the full name in a tooltip. Click the Name, Last active or Pages header to sort (it starts on Last active, newest first; click again to reverse). The whole row opens the PDF on click or Enter, rows are keyboard-focusable with arrow-key movement, and below about 860px wide only Name and Actions are shown. The grid view is unchanged.
- The list view's always-visible trash icon is replaced by a "⋯" menu that appears only on row hover or keyboard focus: Open, Show in folder, and Remove from Recent, which notes that the file stays on disk.

### Added
- Find in document. Press Ctrl+F in the reader, or click the magnifier in the left toolbar, and a small find bar opens over the top-right of the page. Matches are marked in blue (never the yellow of your highlights or the orange of voice), the current one more strongly, and the page moves to it; "3 of 17" says where you are. Enter goes to the next match and Shift+Enter to the previous one (the arrow buttons do the same), and Esc closes the bar and gives the page back the keyboard. The search starts from the page you are on and wraps round, shows the first matches while a long document is still being searched ("Searching…"), and on a scanned PDF with no text layer says "No searchable text in this PDF" instead of "No results". Keyboard and mouse only for now; a voice equivalent is planned.
- Only one Lector runs at a time. Starting it again brings the window you already have to the front (un-minimising it) instead of opening a second one. Lector can also be started with a PDF (`python -m lector report.pdf`); if it is already running, that file opens in the existing window, exactly as if you had dropped it there, so Reading still asks about unsaved highlights first.
- Search on Recent and Favorites. The box that used to sit unused at the top of Home now filters the list as you type, by file name, in both grid and list views, and is named for the page ("Search Recent", "Search Favorites"). The count shows "3 of 12 files" while filtering, and a search with no results says `No PDFs match "…"` with a Clear button. The x in the field clears it, Esc clears it and closes the field, and Ctrl+F or "/" jumps to it. It clears and closes when you switch pages. (It is an icon until opened; see Changed.) Keyboard and mouse only for now; voice search is a later addition.
- Ctrl+O opens the Open PDF dialog from Home, Settings and the reading view (it opens Home's dialog after the usual unsaved-highlights check). It was already available by voice and by button, but had no keyboard shortcut.
- Drag and drop: drop a PDF anywhere on the window to open it. A cue covers the window while a file is over it. From the reading view it first asks about unsaved highlights; anything that isn't a PDF is refused with a message.
- The empty Recent screen is now a proper first-run card: a document icon, "Open PDF", "or drop a file anywhere in this window", and a "TRY SAYING" row of example phrases. The phrases come from the same list as "What can I say?", so they only ever suggest commands that work.
- Voice commands that work on every screen: "open a PDF", "open settings", "go to Recent" and "what can I say". On Recent, "open number 3" opens that file by its position on screen.
- "What can I say?" is now available on Home and Settings (a button in the sidebar's voice box, or by voice), showing that screen's commands.
- Settings now has the sidebar voice box Home has, so you can tell whether voice is listening.
- Screen readers now hear the voice box's state ("Voice ready", "Listening", what was heard, "Voice unavailable"), once per change rather than on every word spoken.
- Favorites' empty state has a "Go to Recent" button.
- Favorites. Every file in Recent now has a star (on the grid card, and on the list row). The Favorites item in the sidebar, on Home and in Settings, opens the list of starred files, with the same grid/list views, sorting, menu and numbered picker as Recent. A starred file stays visible with a filled star; an unstarred one shows its star on hover or keyboard focus. Favorites are kept apart from Recent, so a starred file stays after it falls off the 20-item Recent list ("Last active" then shows a dash until it is opened again). Starring changes nothing on disk, and removing a file from Recent leaves its star alone. By voice (Home): "open favorites" / "show favorites", "show recent files", "favorite recent" / "star recent" (the most recently opened file; say it again to unstar) and "favorite a file" / "star a file" (numbers every file so you can say which); they appear in "What can I say?" under Favorites. "Remove recent" and "remove a file" ask you to switch back to Recent first while Favorites is showing.
- "Show in folder" (Recent list view menu) opens File Explorer (Finder on Mac) with the PDF selected.
- Removing a file from Recent, from the grid, the list menu or by voice, now ends on a "Removed from Recent. The file stays on disk." toast with Undo, which puts the entry back where it was, reading position included. If Recent has filled up in the meantime, Undo says so instead of pushing the oldest file out, and removing a file that is already gone shows no toast.
- Scrollbars auto-hide everywhere — the Reader, Home, the Open PDF dialog's tree and file list, "What can I say?", Settings, onboarding and the window's own scrollbar — through one shared implementation (`frontend/shared/scrollbars.css` + `frontend/js/scrollbars.js`). At rest the thumb is invisible but its gutter stays reserved, so nothing shifts. Any activity — mouse movement, wheel, click, key press, touch, scrolling, a focus change, or real voice activity (push-to-talk, the wake phrase being heard, a transcript arriving, a command running) — shows every scrollbar at once, and they fade out 1.5 seconds after the last activity. A thumb you are hovering or dragging stays visible. The always-on wake-phrase listening does not count as activity, or scrollbars would never hide. Reduced-motion users get no fade, and forced-colors (High Contrast) users never have them hidden. The visible thumb is at least 3:1 against every surface in all three themes. This replaces the per-element `.themed-scroll` class, which is removed; `tests/test_scrollbars.py` fails if scrollbar styling appears anywhere else or if `scrollbar-color`/`scrollbar-width` (which override the auto-hide in Chromium) are used.

They aren't wired into screens yet; later phases of the UI pass adopt them.

- Home screen with sidebar navigation and "Open PDF" button (native file dialog).
- PDF rendering in book layout via PyMuPDF — opens and displays any PDF file.
- Page navigation: Previous/Next buttons and arrow keys / Page Up / Page Down.

- Mouse-based highlighting (Milestone 3): a toggleable highlight tool (toolbar button or `H` key) arms character-level drag selection over the rendered page — a drag can stop mid-word, the same as selecting text in Adobe Reader; on release, the selected text is written as a real PyMuPDF highlight annotation (`features/annotations/highlighter.py`), not a UI overlay, so it's visible in any standard PDF viewer.
- Save-changes confirmation dialog (`Ctrl+S` / `Cmd+S`): "Save a copy" (pre-selected, prompts a native Save-As dialog) vs. "Overwrite the original" (incremental in-place save), with a "Don't ask again" checkbox that persists the choice via `QSettings` (`features/settings/store.py`). The dialog is triggered only by an explicit Save action and never fires automatically as a side effect of highlighting.
- Continuous-strip reading layout (Milestone 4): a toolbar toggle switches between book layout (one bounded page card) and strip layout (all pages rendered in a scrollable column with a subtle page-break marker between them). Mouse-based highlighting works in both layouts, correctly targeting whichever page was actually dragged on.
- Settings screen (`features/settings/view.py`), reachable from the Home sidebar: a live theme picker (Light/Dark/Sepia, applies instantly across the whole app and persists via `QSettings`), a "When I save highlights" section wired to the same save-behavior preference the save dialog uses, and a Voice activation section shown as an inert preview (Milestones 5 and 8 wire it up).
- Dark and Sepia themes (`shared/theme.py`): the 8 base tokens come from `docs/DESIGN_SYSTEM.md`'s provisional table; every other token needed to fill out the full palette is this implementation's own interpolation and still awaits the doc's called-for readability/contrast check.
- Recent files: the last 10 opened PDFs persist via `QSettings` (path + timestamp) and render as a card grid on Home, replacing the empty state once at least one file has been opened; clicking a card reopens that file.
- Recent-file cards now show a real thumbnail of the PDF's first page (rendered via PyMuPDF) and its page count, instead of a blank placeholder box — matching the mockups' card design.
- Undo/redo for highlights: toolbar buttons (next to the highlight tool) plus `Ctrl+Z` / `Ctrl+Shift+Z` (and `Ctrl+Y` on Windows) undo or redo the most recently added highlight, across page and layout changes. Buttons are disabled when there's nothing to undo/redo.
- Clicking the zoom percentage in the topbar opens a slider popover for continuous zoom, instead of only being able to step by 25% via the toolbar buttons. Backed by a new `set_zoom` call (`document.py`/`api.py`) that clamps directly to an arbitrary value rather than stepping from the current one.
- Resume reading where you left off: each document's last page and layout (book or strip) are remembered, and reopening it from Recent returns you to both. A new Settings section, "When I reopen a PDF", chooses between "Continue where I left off" (the default) and "Always start at the beginning", which opens every PDF on page 1 in book layout. Position is stored on the document's recent-files entry in `settings.json`, so it is pruned along with the 10-item recent list rather than accumulating forever, and it is written only when the page or layout actually changes — not on every scroll tick. A page recorded against a file that has since become shorter is clamped to the last page instead of dropping you back to page 1.
- Resume reading now also remembers zoom: whatever zoom level (toolbar step buttons or the zoom-popover slider) a document was left at is restored the next time it is reopened from Recent, alongside its page and layout, under the same "Continue where I left off" preference — no separate setting.
- First-run onboarding placeholder (Milestone 4 stub): the very first launch now opens a Welcome screen instead of dropping straight into Home. It introduces the two first-run steps the full flow will cover — microphone permission and how you prefer to start talking — but does not yet perform either: the controls are visibly inert and the screen says plainly that it is a placeholder. "Skip for now" and "Start reading" both continue to Home, and the screen does not come back.
- Push-to-talk voice recognition (Milestone 5): hold `Space` anywhere in Lector and speak; release when you are done. Recognition runs entirely offline through Vosk against a fixed command vocabulary rather than open transcription, so unfamiliar speech is discarded instead of being guessed at. A microphone indicator (in the reading view's footer, and in the Home sidebar) shows whether voice is ready, listening, or unavailable, and echoes the phrase it heard. Nothing acts on a recognized phrase yet — navigation commands follow in the next milestone.
- Voice stays optional and silent about it: if the offline speech model is not installed, the indicator simply reads "Voice unavailable" and everything else works unchanged. The model is not shipped in the repository; `python scripts/fetch_vosk_model.py` downloads it.
- Holding `Space` while typing in a text field, while a dialog is open, or on a focused button types a space or presses the button as usual instead of starting to listen. Switching away from the Lector window while holding the key stops listening rather than leaving the microphone open.
- Voice navigation commands (Milestone 6): spoken phrases now actually move you through the document — "next page" / "turn the page" / "forward", "previous page" / "go back", "go to page twenty three" (or "page 7"), and "scroll down" / "scroll up". Each intent accepts several phrasings rather than one exact wording, and edit-distance tolerance (`features/voice/fuzzy.py`) means a single misheard character — "text page" for "next page" — still lands on the right command. A phrase that matches nothing does nothing, and the footer says "Not a command I know" rather than guessing at an action that would lose your place. Spoken scrolling moves most of a screen at a time so the line you were reading stays on screen, and turns the page when the current one runs out, landing at the top of the next page (or the bottom of the previous one, going back). Commands are ignored while a dialog is open, and mouse/keyboard navigation is unchanged — voice calls the same functions the buttons do.
- Voice highlighting (Milestone 7): saying "highlight" followed by a phrase — e.g. "highlight the quick brown fox" — fuzzy-matches it against the words currently on screen and writes a real highlight annotation over the best match, the same way dragging with the mouse does. Matching is scoped to the visible viewport only (never the whole document), and ties go to the first occurrence in reading order, so a repeated phrase always lands on the same place. "Highlight the sentence" (or "this sentence") widens the match outward to the nearest sentence punctuation in both directions, still on the same page. While a key is held for push-to-talk, the recognizer's vocabulary is temporarily widened with the visible page's own words, so it can hear text that was never in the fixed command grammar. The footer names the outcome — "Highlighted 'the quick brown fox'" or "Couldn't find '...' on this page" — so a missed match is never silently indistinguishable from a dropped command. "Save the file" / "save the document" / "save the pdf" / "save" are now recognized as their own command, routed through the same save-or-discard dialog `Ctrl+S` uses — highlighting by voice never saves as a side effect.
- An amber "Listening here" outline now draws directly on the page while a push-to-talk hold is in progress, in book and strip layouts alike — the on-page counterpart to the footer mic pill's amber color, using the same `--color-voice-focus` token (`docs/DESIGN_SYSTEM.md`'s third wash state, after selection and highlight). It outlines the exact region(s) voice matching is scoped to, computed in the same pass as the point-based regions sent to the backend so the two can never drift apart; in strip layout, where the viewport can straddle two pages, it draws one box per partially-visible page. The outline disappears as soon as the hold ends.
- Wake phrase (Milestone 8): with wake listening on, Lector keeps a low-cost, grammar-constrained recognizer open for one phrase only — "Hey Lector" — and opens a command window when it hears it, so a command can be given without touching the keyboard. The idle recognizer's vocabulary is the wake phrase and nothing else (`features/voice/wake.py`), so ordinary conversation in the room is discarded by the recognizer itself rather than transcribed and then filtered. Only final results trigger it: partial results are retractable, and acting on one produced a window that opened on a half-heard word. The footer mic pill shows idle wake listening in a quieter state than an active capture, because the microphone is genuinely open and it would be dishonest to render that identically to "off".
- Settings > Voice activation: push-to-talk and the wake phrase are now independent toggles, and either, both, or neither can be on — neither is presented as the recommended one. The push-to-talk key (`Space`) and the wake phrase are shown as the facts they currently are, labelled "fixed for now", rather than as controls that look rebindable but are not.
- "What can I say?" panel: a categorized command reference (Moving around / Highlighting / The app itself), opened from the reading view's help button or its footer link. Every phrase listed is generated from the live command grammar (`features/voice/reference.py`) rather than written out by hand, and a test feeds each advertised phrase back through the parser, so the panel cannot offer wording the recognizer would reject. Each command shows its alternative phrasings, what it does, and the keyboard or mouse equivalent — `docs/PRD.md`'s parity requirement made checkable. A search field filters the list live. The panel omits a "Finding words" category because in-document search has not been built; an empty category would read as a broken feature rather than an absent one.
- First-run onboarding is now the real two-step flow, replacing the Milestone 4 placeholder. Step one asks for microphone access — the request genuinely opens the microphone briefly, because that is the only way either OS raises its permission prompt — and a refusal comes back as a plain sentence, not an error. Step two chooses how listening starts. Every exit from the screen, including skipping, lands in the same fully working app: if there is no microphone access, no activation mode is switched on, because an indicator claiming to listen without a microphone is worse than one that says voice is off.
- Closing the app window (the close button or Alt+F4) with unsaved highlights now shows the same save-or-discard prompt the Library back button uses, instead of losing them silently (Milestone 8.1). Choosing "save" or "discard" closes the window; cancelling leaves it open. Closing with no document open, or with nothing unsaved, closes immediately as before.
- Audio preprocessing on the capture path (Milestone 8.2): every chunk captured for recognition — push-to-talk, wake listening, or a post-wake command — now passes through gain normalization and adaptive noise suppression before reaching Vosk, instead of going to the recognizer raw. A Silero VAD model (`assets/silero_vad.onnx`, fetched by the new `scripts/fetch_vad_model.py`, same gitignored/bundled-at-packaging pattern as the Vosk model) also runs on each chunk; in the post-wake command window, 0.6 seconds of continuous silence after speech has been heard now closes the window early, so a short command doesn't sit listening for the rest of the fixed window after the reader has already finished. Like the Vosk model, a missing VAD model degrades quietly — noise suppression and gain normalization still run, only the extra early-close behavior is unavailable.
- Confidence-based clarification loop (Milestone 8.3): a phrase that misses the grammar's confident-match threshold is no longer silently discarded. Vosk now returns up to 5 n-best alternatives per final result; the resolver first checks whether the top guess or any alternative parses as a known command outright, and only if none do does it fall back to fuzzy near-miss scoring against the grammar's phrase list. A near-miss (closer than the confident-match threshold but not close enough to act on) surfaces as a "Did you mean '<candidate>'?" hint in the reading view's mic pill instead of doing nothing; repeating the phrase clearly is what confirms it; a dedicated voice yes/no confirmation loop is left for the Milestone 8.4 router. Commands whose phrasing is ambiguous when heard in isolation (`goto page <n>`, `highlight <text>`) are excluded from near-miss matching so a misheard fragment can't be "corrected" into the wrong intent.

- Fixed a follow-up to the above: zooming while positioned near a page boundary could still jump the view a whole page forward or back even with no scrolling in between. The scroll-restore anchored to "the current page's top plus a fraction into it," but the old (CSS-scaled preview) and new (freshly measured) page heights round slightly differently, so near a boundary the computed position could land a hair into the next page — which then read back as a different "current page" entirely. Growing the pages therefore slid what the user was reading down past a fixed scroll offset, landing the view on an earlier page; shrinking them landed it on a later one; and each step of a zoom burst compounded the last. The debounced rebuild's scroll anchor was measured after all of this had already happened, so it faithfully preserved the drifted position instead of correcting it. The preview now re-anchors the scroll position in the same synchronous step that resizes the pages, so the view never moves off the page it started on. Simulated over a 357-page strip in a browser: zooming from 100% to the 400% maximum starting on page 3 previously ended on page 1, and zooming out to 50% from page 20 ended on page 38; both now stay put.
- Page images no longer animate their width/height when zooming (`transition: width/height` on `.page-surface`). The transition made resized pages report mid-animation sizes to the scroll-anchoring above, which has to measure them to keep the view in place; zoom now resizes instantly, as it does in other PDF readers.
- Also corrected, while tracking the above down: the scroll anchor the debounced zoom rebuild restores was the scrollbar's raw position ratio, `scrollTop / (scrollHeight - clientHeight)`, which drifts on its own because neither the viewport height nor the strip's fixed furniture (the 20px gap between every pair of pages, the scroller's 24px padding) scales with zoom. Holding that ratio constant lands at `scrollTop * (k*H - V) / (H - V)` rather than the correct `k * scrollTop`, an error of roughly `position-in-document × viewport-height × (zoom-factor - 1)` — measured at -131 to +183px deep into a long document, enough to change the current page on its own in four of nine tested zoom scenarios. The rebuild now anchors to the current page plus the fraction of that page's height the viewport top sits at, recorded against the page element's own index (so the scroll tracker cannot move it out from under the restore) and clamped to that page's extent (so it cannot flip to a neighbouring page, which is what sank an earlier page-relative attempt). Exact in all nine scenarios.

Same defect as the strip-layout bug above, and it now goes through the same anchoring, in both the preview and the rebuild.

Sidebar/toolbar icon containers (`.nav-item`, `.btn` icon slots) now reserve their final size up front instead of starting at zero size until their SVG finishes loading, removing the layout pop/shift that happened on every page load. Note: page transitions still use full `window.location.href` navigation between separate HTML documents, which has an inherent brief reload flash of its own — switching to a single persistent shell with in-place view swapping would remove that too, but is an architecture change beyond this fix; flagging for a separate decision rather than doing it silently.
- Switching theme while reading in strip layout no longer resets the visible scroll position to page 1: the theme switch rebuilds the reading view and reloads the document before that view becomes the visible one again, so the strip's scroll area had no real viewport size yet and silently clamped the scroll-to-page call to 0. The reading view is now made current before the reload, so the scroll lands on the correct page.
- The highlight tool now works in strip layout, not just book layout: dragging over any page in the strip writes the highlight to the page actually dragged on, instead of always writing to whichever page the document happened to consider "current" (a distinction that didn't exist in book layout, where only one page is ever visible, but could silently misplace highlights once multiple pages were visible at once).
- Switching theme in the reading view no longer feels laggy and no longer silently discards unsaved highlights: every theme change previously reopened the PDF from disk and re-parsed it from scratch (on top of rebuilding every screen and, for the Home screen, re-rendering a thumbnail for every recent file), which also meant any highlight added but not yet saved was lost the moment the theme changed. The already-open document (including any unsaved highlights) is now carried over into the rebuilt reading view instead of being reopened, and recent-file thumbnails are cached and only re-rendered when the underlying file actually changes.
- Clicking the "Library" back button no longer silently discards unsaved highlights: it previously navigated away immediately with no save check, unlike the explicit `Ctrl+S` save flow. It now prompts to save first (the same dialog and save-behavior preference `Ctrl+S` uses) if there are unsaved changes, and cancelling the prompt keeps you on the page instead of losing the highlight.
- Fixed a regression from the above: the save-changes prompt shown on the "Library" back button only offered Save or Cancel, with no way to leave without saving — clicking Cancel correctly kept the highlight, but left no path back to the Library at all, trapping the user on the reading screen. The prompt now offers a "Don't Save" option (in addition to Cancel and Save) when reached via the back button, which discards the unsaved highlight and navigates home; the explicit `Ctrl+S` save flow is unaffected and still only offers Save/Cancel.
- Tooltips were still not reliably visible after the earlier Fusion-style fix, because Windows' native tooltip compositor can ignore the app's QSS styling regardless of the active Qt style. The left rail's tooltips (highlight tool, undo/redo, previous/next page, "What can I say?") are now drawn as a fully custom, app-owned popup instead of relying on the native `QToolTip`, so their appearance no longer depends on OS tooltip theming.
- Strip layout could render with several pages missing and two unrelated pages' content butted directly against each other (e.g. page 1's title clipped and immediately followed by a much later page), when navigation (arrow keys, Previous/Next, or rapid voice commands) happened while the strip's first full-document render was still in flight. `refreshStrip()` had no guard against overlapping builds, so a second call would clear and start re-rendering the strip concurrently with the first, interleaving both builds' pages into the same container. Overlapping calls now wait on the in-flight build instead of starting a second one.
- Book and strip layouts could render on top of each other, with the book layout's single bounded page card floating over the strip's continuous pages beneath it, producing visibly merged/overlapping page content. `.book-scroll, .strip-scroll { display: flex; ... }` unconditionally set `display` on both elements; per the CSS cascade, author rules always win over the browser's built-in `[hidden] { display: none }` rule, so toggling the `hidden` attribute in JS (used to switch between the two layouts) had no visual effect — whichever layout wasn't active kept rendering, absolutely positioned, underneath or over the active one. Added explicit `.book-scroll[hidden], .strip-scroll[hidden] { display: none; }` rules so hiding actually hides. This was likely also the real cause of the strip-layout "pages merged" bug reported and (incompletely) fixed above.
- Strip layout's page-to-page gap is now visible again as a result of the fix above (previously obscured behind the wrongly-still-visible book layout page card): pages are separated by a plain canvas-colored gap, matching the continuous-scroll look of Adobe Reader / other PDF viewers.
- Strip layout's page indicator no longer freezes at whatever page was current when you switched into strip mode: scrolling now tracks whichever page has scrolled past the top of the viewport and updates the page number (and the backend's current-page pointer, so Previous/Next/Save behave correctly afterwards) to match.
- Highlighting in strip layout no longer triggers a full rebuild of every page in the document (blanking the whole strip and re-fetching all 357 page images one at a time) just to reflect one new highlight — only the page actually highlighted is re-rendered in place.
- The page-number box and the "of N" label next to it were vertically misaligned in the topbar; both now share the same line-height/height so they sit on the same baseline.
- The reading pane's scrollbar (book and strip layouts) now uses a slim, subtle thumb matching the mockups, instead of the OS's default wide scrollbar with arrow buttons.
- The "Save changes?" dialog no longer matched `docs/DESIGN_SYSTEM.md`'s mockup: it rendered as a native-decorated window (OS title bar and close button, no dim backdrop), its radio buttons relied on Qt's default indicator instead of the mockup's explicit ring-with-centered-dot style, the selected option's border didn't update live when the user changed their selection, and internal spacing didn't match the mockup. It's now a frameless overlay centered over the reading window with a dim scrim behind it (`src/lector/features/annotations/save_dialog.py`); radio indicators are explicitly styled (18x18 ring, `#D2CCC2` unchecked / `#3E6259` checked, with a centered 10px dot when checked); each option row's border switches live between a 1px `#D2CCC2` unchecked state and a 2px `#3E6259` checked state as selection changes; and row padding/gap now match the mockup (18px internal padding, 12px between rows). Blurring the reading view behind the dialog is a separate, not-yet-implemented future task — the backdrop is a plain dim for now.
- The reading pane's scrollbar is now thinner (6px) to sit closer to the mockups' slim, understated look, instead of the earlier wider first pass.
- Switching between book and strip layout no longer snaps back to the top of the current page — it now preserves how far down the page you'd scrolled and restores the same relative position in the new layout.
- Clicking Undo right after highlighting in strip layout could jump the view to page 1 instead of staying on the current page: undo (like zoom) forces a full strip rebuild since it can affect any page, and while `stripContainer` is briefly cleared during that rebuild, the browser clamps the strip's scroll position to 0 and fires a `scroll` event — which the page-indicator scroll-tracking added above was misreading as "the user scrolled to page 1" and syncing back to the backend. Scroll-tracking now ignores scroll events that fire while a strip rebuild is in flight. (Confirmed via code review that book layout's Undo was never affected — the backend never changes the current-page pointer on undo.)
- Fixed a regression from the previous "preserve scroll position" fix: toggling book→strip would land a page further down (looking like it had scrolled to the next page), and toggling strip→book would land a few lines above where you'd actually been. The two layouts' scroll-fraction calculations measured different things — book mode computed a fraction of the scroll container's total overflow range, strip mode a fraction of the page's own rendered height — so a fraction computed in one layout was meaningless applied in the other. Both directions now use a single formula based on `getBoundingClientRect()` (comparing the scroll container's edge to the current page image's edge), which measures the same "how far scrolled into this page" quantity regardless of which layout is active.
- Highlighting in book mode then switching to strip layout, clicking Undo/Redo in strip layout, and zooming in/out in strip layout could all make the reading pane appear to snap to (and get stuck on) page 1: rebuilding the strip cleared its container up front and then re-rendered every page one at a time over the pywebview bridge, so for a large document the strip (and its scroll position) collapsed to zero height for the whole, potentially very slow, duration of the rebuild — and undo, redo, book-mode highlighting, and zoom all forced this same full-document rebuild even though undo/redo/highlighting only ever change a single page. `buildStrip()` now assembles the new pages in a detached fragment and swaps it in with one `replaceChildren()` call, so the strip keeps showing its old (correctly scrolled) pages until the new ones are ready instead of collapsing mid-rebuild; and undo/redo/book-mode-highlighting now patch just the single page that actually changed (the backend's `undo_highlight`/`redo_highlight` now report which page index was affected) instead of forcing a full rebuild. Zoom still needs to re-render every page (their pixel dimensions change), but no longer visibly freezes on page 1 while doing so.
- Zoom in/out in strip layout lagged noticeably: every click (or held key) triggered its own full re-render of every page in the document, so a few quick clicks queued up that many full rebuilds back to back. Zoom actions now update the zoom level and apply an instant CSS scale preview to the already-rendered pages immediately, and debounce the actual (expensive) re-render until 300ms after the last zoom step — clicking or holding zoom in/out now feels immediate, with a brief settle before the sharp re-rendered pages swap in. The same debounced path is used by the new zoom slider.
- Strip layout's pages had no shadow, unlike book layout's page card, making the two layouts look inconsistent when switching between them. Strip pages now use the same shadow (`box-shadow: 0 4px 24px rgba(0,0,0,0.176)`) as book layout's page card.
- The reading pane's horizontal scrollbar (shown when zoomed in past the viewport width) looked noticeably bulkier than the slim vertical one: the custom `::-webkit-scrollbar` styling only set `width`, which controls a vertical scrollbar's thickness, leaving the horizontal scrollbar's thickness (`height`) at the browser default. Both are now sized to match.
- The Open/Save-As dialog's "Up" button left drive roots (Windows' `C:\`, Mac's `/`) a dead end, with no way to reach any other drive or mounted volume once there. A directory listing with no parent now prepends a synthetic, numbered "Other Drives" row (`dialog_browser.list_drives()`) that opens a drive/volume picker: every existing Windows drive letter A–Z on Windows, or `/` plus whatever's mounted under `/Volumes` on Mac. Picking a drive navigates into it the same way picking a folder does.

- Page titles use the serif display face on Home ("Recent") and in the Reader's top bar, matching Settings and the dialogs.

- **Highlighting now shows the selection before it applies the highlight**, the way Adobe Reader and other desktop annotators do. Dragging over text with the highlight tool armed washes the covered words in the selection color as the cursor moves — snapping to whole words, and running edge-to-edge across every full line the drag spans — and only on release does that shape become the yellow highlight. Previously nothing at all happened until the mouse came up, so there was no way to tell what was about to be highlighted, or that the drag had registered, until it already had been. Pressing Escape mid-drag, or turning the highlight tool off, abandons the selection without writing anything; a plain click still highlights the single word clicked, as before.
- Highlight annotations are now written as one quad per line of the selection instead of one per word, so a highlighted line is a continuous bar rather than a row of blocks broken at every space. - **Architecture: GUI layer switched from PySide6/Qt to pywebview.** The app is now a Python backend (`src/lector/api.py`, a `js_api` bridge exposed to the page) driving an HTML/CSS/JS frontend (`frontend/`) rendered in the OS's native webview, instead of hand-built Qt widgets.
